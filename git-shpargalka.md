# Аварии

## Авария А: испортила файл, не коммитила.

**Что случилось:** удалила половину текста в about.md и сохранила, изменения не закоммичены.

**Как понять, что это оно:**

изменён по сравнению с последним коммитом,не добавлены в индекс (git add не делала)

Changes not staged for commit:
modified: about.md

use "git add <file>..." to update what will be committed - эта строчка которая предлагает использовать git add чтобы обновить то что попадет в коммит
(use "git restore <file>..." to discard changes in working directory) - эта строчка которая предлагает вернуть изменения в файле

**Команда:**

git restore about.md, возвращает файл к версии из последнего коммита, стирает правки безвозвратно

**Что было бы без неё:**

половина текста так и была бы удаленной и восстановить ее можно было бы вручную

## Авария Б: в коммит попал лишний файл.

**Что случилось:**

Я создала файл secret.txt записала в него пароль, файл попал в коммит через git add . , но не запушила.

**Как понять, что это оно:**

с помощью git show --stat HEAD я посмотрела содержимое последнего коммита и увидела, что добавлен один файл secret.txt, файл не запушен т.к я не делала git push

**Команда:**

git reset --soft HEAD~1 - я ушла на один коммит назад
и команда отменила последний коммит, но сам файл не трогаю, а оставляю в индексе.

git restore --staged secret.txt. - команда убирает файл из индекса, а в папке он остаётся

.gitignore - git перестаёт видеть сам файл

**Что было бы без неё:**

если бы я запушила файл оказался бы на GitHub, в моем public-репозитории, и его мог бы открыть и прочитать любой человек в интернете
удалить его оттуда просто так нельзя,запушенный коммит не переписывается, даже если потом удалить файл новым коммитом, старый коммит с паролем останется в истории и его можно будет посмотреть

## Авария В: начала работать в main вместо ветки.

**Что случилось:**

Сделала правку в about.md и сохранила файл, но не закоммитила, и всё это на ветке main.

**Как понять, что это оно:**

вывод git status: через on branch main + modified: about.md - я на ветке main сделала изменения в файле about.md но не закоммитела их

**Команда:**

Набрала git switch -c oops-branch: создала новую ветку с названием oops-branch и сразу на неё переключилась. Правка не потерялась и не откатилась, она просто переехала в новую ветку, а main остался чистым.

**Что было бы без неё:**

если бы я не заметила аварию и сделал git commit, ревью бы не случилось , правка попала бы сразу в main, обойдя PR

### Если правки уже закоммичены в main

как понять:
в git status пишут Your branch is ahead of 'origin/main' by 1 commit это значит что коммит добавлен в локальную ветку main

**Команды:**

`git branch oops-branch` — создает ветку на текущем коммите , коммит сохранен на ветке, а я остаюсь на main

`git reset --hard origin/main` — возвращает локальный main к тому что лежит на GitHub. Лишний коммит из main исчезает.

`git switch oops-branch` — перключает в ветку с коммитом

**Почему reset --hard здесь не страшен:**

Потому что все равно возвращает локальный main и коммит остается на отдельной ветке

## Авария Г: плохой коммит уже запушен.

**Что случилось:**

я удалила всё содержимое about.md, закоммитила и запушила и командой revert вернула файл

**Как понять:**

703f96e (origin/emergency-drill) Break about page

origin/emergency-drill - значит плохой коммит уже на github и он запушен

**Команды:**

git revert HEAD - не стирает плохой коммит
создает новый, который удаленные строки возвращает

**Что было бы без неё:**

нельзя reset, потому что reset не гарантирует что этого коммита нет у другого человека в другой локальной ветки

А без revert на GitHub так и остался бы пустой about.md.
